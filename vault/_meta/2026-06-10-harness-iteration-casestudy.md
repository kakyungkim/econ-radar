# econ-radar 하네스 — 구조 정리 & 개선 일지 (2026-06-10)

> 포스팅·발표용 사례 정리. econ-radar가 무엇이고, 어떻게 짜여 있으며, 사용자 피드백을 받아 하루 동안 어떻게 진화했는지를 담는다.

---

## 1. econ-radar 한 줄 정의

매일 신뢰 경제지(국내외)를 스캔해 **산업구조·투자·유망 기업** 3렌즈로 정리하고, 그 누적을 **동향 리포트 → 블로그 → 책**으로 키우는 **개인 경제 인텔리전스 하네스**. 전 분야를 다루되 제약/바이오/AI에 비중을 둔다.

핵심 발상: 뉴스를 "읽고 끝"이 아니라, **에이전트 팀이 매일 수집·분석·집필하고 옵시디언 vault에 누적**해 시간이 갈수록 자라는 지식 자산으로 만든다.

---

## 2. 3층 구조

- **1층(매일)**: 뉴스 수집 → 분석 → 뉴스레터 → 문체 검수 → HTML/푸시 → vault 정리. (아래 파이프라인)
- **2층(자산)**: `vault/` = 옵시디언 vault. 태그·`[[위키링크]]`·주제 MOC로 누적.
- **3층(저술)**: 누적분을 동향 리포트·블로그·책으로 집필.

품질 기준선: `vault/_meta/benchmarks.md`(본받을 매체·도구)와 `vault/_meta/korean-style-samples.md`(실제 한국 경제기사 문체 표본).

| **market-analyst** | 1 | 산업구조·투자 렌즈 분석(밸류체인 변화, 테마·리스크·기회, 양면 시각). |

## 4. company-scout가 하는 일 (오늘 신설)

**유망 기업·주목 플레이어 분석가.** 같은 뉴스를 "어떤 기업이 떠오르나" 렌즈로 본다. (기존 'career-analyst'(커리어·일의 미래)를 대체.)

- 오늘 뉴스에서 **주목할 기업 3~5곳**을 고른다(국내·해외, 제약/바이오/AI 비중↑).
- 기업마다: ① 무슨 일(사실, 과거형) ② 왜 주목(시장 위치·기술·모멘텀) ③ 지켜볼 점(다음 이벤트·리스크).
- 제약/바이오는 **신약개발 총괄 시점**으로 한 단계 더: 파이프라인 위치·모달리티·경쟁/파트너십·약가.
- 큰 신생 구도(ADC 피하전환 인프라, AI 컴퓨트 임대 사업자 등)도 "주목 플레이어"로 잡는다.
- **안전선**: 매수·매도·입사 권유 금지(정보·시나리오로). 출처 없는 숫자 금지.

**왜 커리어 대신 유망 기업으로 바꿨나**: 사용자 목표(실제 투자 + 신약개발 총괄 시점 + 책)에 비춰, "커리어/일의 미래"는 매일 다루기엔 반복적이고 덜 실용적이었다. "유망 기업"은 투자 판단과 R&D 경쟁 구도 양쪽에 직접 닿는다. (일의 미래 테마는 3층 저술에서 선택적으로.)

## 5. 1층 파이프라인

```
news-scout            → vault/raw/news-YYYY-MM-DD.md
  ├ market-analyst    → vault/analysis/market-YYYY-MM-DD.md   ┐ 병렬
  └ company-scout     → vault/analysis/company-YYYY-MM-DD.md  ┘
newsletter-editor     → vault/daily/YYYY-MM-DD.md
style-critic(윤문)    → vault/daily/YYYY-MM-DD.md (덮어쓰기)
report-renderer       → vault/html/*.html, vault/push/*.md
knowledge-curator     → vault/topics/*.md
```
외부 발송(메일·푸시·발행)은 **항상 사람 승인 뒤**. 자동 발송 없음.

## 6. 오늘의 개선 일지 (피드백 → 하네스 변화)

> 핵심 교훈: **주관적 불만("어색하다")을 매번 재발 방지되는 구조 변화(프롬프트 규칙·표본·구조)로 전환**했다. 같은 지적을 두 번 듣지 않게 만드는 게 하네스 엔지니어링.

| # | 사용자 피드백 | 한 일 (재발 방지) |
| --- | --- | --- |
| 1 | "맥북 닫아놔서 미발행됐나? 지금 돌려줘" | 전체 파이프라인 수동 실행, 오늘치 생성 |
| 2 | "AI스럽고 읽기 힘들다" | style-critic·newsletter-editor에 **'읽기 힘든 AI 문장 5가지' before/after 규칙** 추가(명사화·만연체·추상 클리셰·조건문 반복·평탄한 종결). HTML 가독성(폰트↑, 강조블록, 경제영어 카드 재설계) |
| 3 | "지어낸 표현 말고 진짜 기사 문체로" | **실제 한국 경제기사 문장 수집** → `korean-style-samples.md` → 두 에이전트의 의무 기준선. 사건 과거형·원화 병기·영문 병기 |
| 4 | "같은 섹션에 ~다/~음/명사 종결이 뒤섞임" | **종결어미 통일 규칙**(한 섹션 = ~다 평서문) 추가, 투자 섹션 정리 |
| 5 | "발음 아이콘 깨짐, 음성이 로봇 같음" | 텍스트 '발음'→스피커 아이콘→(사파리 file:// 깨짐) **인라인 SVG**로 해결. 음성: **자연스러운 영어 음성 자동 선택** + 줄표 끊어읽기 + 크롬 권장 |
| 6 | "'왜 중요한가' 라벨 어색, 화제도 어색" | 라벨 **Key Point**로 변경. '오늘의 화제' 문장 재작성 |
| 7 | "커리어보다 유망 기업이 낫지 않나" | 세 번째 렌즈 **커리어 → 유망 기업** 교체(**company-scout** 신설, 관련 파일 일괄 배선) |
| 8 | "Key Point로 인사이트가 갈음되나, 주관 인사이트 필요?" | 핵심 항목을 **Key Point(객관 사실) + 💡 인사이트(주관 의견)** 두 줄로 분리 |
| 9 | "네 이미지 완성도 낮으니, 디자인 에이전트는 이미지 생성 프롬프트만 만들게" | **image-prompt-smith** 신설(외부 이미지 AI용 프롬프트 작성, 직접 SVG/PNG 생성 안 함) |

### 발표/포스팅 앵글(초안)
- "주관적 피드백을 객관적 자산으로": '어색하다'는 막연한 불만을 **실제 기사 표본 + 명시적 규칙**으로 바꾼 과정.
- "에이전트 하네스의 자기수정": 같은 지적을 두 번 안 받게 프롬프트·구조에 반영하는 루프.
- "사람 승인 게이트와 안전선": 투자 권유·발송 자동화를 막는 설계.
- "렌즈는 고정이 아니다": 커리어→유망 기업처럼, 사용자의 북극성에 맞춰 분석 렌즈를 갈아끼우는 유연성.
