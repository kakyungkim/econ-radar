# longform-authoring (동향·블로그·책 저술 매뉴얼)

vault에 쌓인 매일의 단편을 공개용·자산용 장문으로 만드는 매뉴얼이다. 3층 작가(trend-synthesizer, content-writer)가 따른다.

## 트리거
- "이번 주/달 동향 리포트", "이 주제로 블로그 써줘", "책 목차/챕터 만들어줘".

## 공통 원칙
- **산문으로 쓴다.** 불릿 나열로 끝내지 않는다(리포트의 근거 목록은 예외).
- vault의 노트를 1차 재료로 쓰고, 모든 주장에 근거 노트/출처를 연결한다.
- 부족한 사실은 검색으로 출처를 확보해 보강한다. 지어내지 않는다.
- 투자 주제도 매수·매도 권유가 아니라 정보·시나리오로.
- 커리어 주제는 "어떤 일이 사라지고 떠오르나(일의 미래)" 관점으로.

## 1) 동향 리포트 (trend-synthesizer)
- 기간(주/월)의 노트에서 반복 신호·변곡점을 추출.
- 구조: 핵심 메시지 3 → 흐름 2~3개(각 근거 노트 링크) → 투자 시사점 → 커리어 시사점 → 다음에 지켜볼 것.
- 저장: `vault/reports/YYYY-Www-동향.md`.

## 2) 블로그 글 (content-writer, 블로그 모드)
- 하나의 주제/동향을 1편으로. 후킹 도입 → 맥락 → 인사이트 → 정리.
- 분량: 읽는 데 5~8분. 제목은 검색·공유를 고려.
- frontmatter `status: draft`(발행 전까지 유지). 저장: `vault/blog/YYYY-MM-DD-{슬러그}.md`.

## 3) 책 (content-writer, 저술 모드)
- `vault/book/outline.md`에 목차를 누적·갱신.
- 챕터는 `vault/book/chNN-{슬러그}.md`. 챕터 간 중복·논리 흐름을 관리.
- 여러 동향 리포트를 묶어 한 챕터의 논지로 구성.

## 문체(톤) — 모든 글 공통
- 사람이 쓴 것처럼 담백하게. AI 상투구 금지: "A가 아니라 B", "~인 셈", "~라고 할 수 있다", 과장·번역투, 오글거리는 비유.
- 전문용어는 한국어(영문) 병기. 용어는 "블로그 소재"(="씨앗" 아님).
- 깊이는 길이가 아니라 맥락·근거·함의에서 — `vault/_meta/benchmarks.md`의 깊이 장치(Why it matters, 1차 자료, 양면 시각, 전략 프레임)를 적용한다.

## 품질 체크
- [ ] 모든 핵심 주장에 근거(노트/출처)가 연결됐는가
- [ ] 산문으로 자연스럽게 읽히는가
- [ ] 매수·매도 권유, 회사 보증 같은 금지 표현이 없는가
- [ ] (블로그/책) status가 draft이고 외부 자동 발행을 하지 않았는가
- [ ] (책) 새 챕터가 outline과 일관되는가

## 발행 승인 게이트
- 블로그·책은 항상 draft로 남긴다. **외부 발행·공개는 사람이 검토·승인한 뒤**에만. 작가는 발행하지 않는다.
